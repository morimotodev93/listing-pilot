# 0009: 読み取り専用の出品候補と共通検証

- 日付：2026-11-16（日本時間）
- 状態：採用・Phase 4.4実装

## 共通契約と責務

`listing_preview_service::get` が商品・公開文章・有効な設定済みカスタム値・画像を組み立て、
安定したIssueコードと日本語メッセージ、準備状況を返す。Reactは検証条件を再実装しない。
IPCは `get_listing_preview({ productId })`、返却DTOはcamelCase。
画像だけはRustが検査したpreviewPathを返し、既存と同じくAPI層でAsset URLへ変換する。
DB相対パスや内部説明メモはDTOに含めない。

listing_titleがNULLの場合だけ管理名を候補とし、titleSourceをproduct_name、
Issueをtitle_fallbackとする。候補を商品に保存しない。説明文には公開用説明文だけを使う。
カスタム値は定義の現在の表示順・名前・単位を使用し、Numberも文字列のまま維持する。
非表示値や未設定項目は含めず、DBには手を加えない。

Issueはタイトル・説明文・価格・画像なし・利用不能画像の順。
利用不能画像のIssueは全体で1件にまとめ、各画像のpreviewPathがNULLなら表示不能と分かる。
Issueなしはready、warningのみはwarning、errorを含めばblocked。
readyは共通の検査を通過した意味であり、販売先ごとの出品条件を保証しない。

## スナップショットと画像の保護

既存の共通メディアpermitを先に取得し、商品・画像・全定義・商品別値を単一のDEFERRED読取
トランザクションで取得する。1つでも失敗すればIPCエラーとし、部分結果を返さない。
DB Mutex解放後にMediaStorage::previewでUUID由来パス、リンク・reparse point、
通常ファイルとしての読取可否を検査する。画像IDと結果を同じ構造体に保持する。
permitは全検査終了まで保持し、既存の画像取り込み・並べ替え・削除・商品削除との競合を防ぐ。
OSロックは既存MediaStorageが保持する。競合時は待機せず既存のmedia_busyを返す。

プレビュー自体はDBもメディアも更新しない。スキーマはVersion 4のままとし、Migrationは追加しない。
CSP・Asset Protocol・Capabilities・通常の保存先は変更しない。
再読み込みは全情報を再取得し、以前の結果を消してから開始する。失敗時は古い結果を表示しない。
API層はStrictModeによる二重取得を避けるため、同一商品の進行中Promiseだけを共有し、完了後は保持しない。

検査後の外部プログラムによるファイル変更を恒久的に防ぐものではない。
画像の全件デコード・SHA-256再計算は行わず、ブラウザーの読込失敗は別途プレースホルダーで示す。
ブラウザー側の失敗ではRustが返したスナップショットのstatusを書き換えない。

## Phase 4.5との関係

CSV固有変換は候補生成・検証から分離して追加する。CSVと画面でタイトル・説明文・属性値・
Issueの生成を別実装しない。画像変更では商品updated_atが変わらないため、出力時は最新の
商品・画像・定義・値を再取得し、必要な完全性検証を行う。保存済みプレビューを出力許可として使わない。
今回CSV・ZIP・自動保存・自動公開は実装しない。
