# 0012: 複数商品を1つの出力単位としてエクスポート

- 日付：2026-11-17（日本時間）
- 状態：採用・Phase 4.6

## 商品選択と確認

ProductListで商品UUIDのSetを保持し、所属グループUUIDで表示を絞る。名前・行番号は選択の識別に使わない。
表示中の全選択／解除は現在の絞り込み結果だけに適用し、非表示商品の選択は保持する。
一覧再取得時は存在しなくなったUUIDを除外する。全解除と選択件数を提供し、0件では開始できない。

開始時に対象UUID配列を固定し、Rustの最新プレビューを全商品について取得する。
商品名・SKU・グループ・出品候補・ready/warning/blocked・商品別Issue・画像総数を表示する。
warningでは全対象の内容と警告への明示承認を必要とし、blockedが1件でもあれば全体を禁止する。
Reactは候補・Issueの判定を再実装しない。読込・出力中の遷移と重複実行は同期refで防ぎ、
確認中は一覧選択を表示せず、カスタム項目設定も操作できなくする。
StrictMode再実行時は同一プレビューPromiseを再利用する。再読込・キャンセル・対象変更で警告承認を破棄する。

## APIと一時トークン

`get_export_batch_preview({input:{productIds}})` と
`export_products({input:{productIds,snapshotToken,warningToken}})` を追加する。
入力はcamelCase、未知フィールドを拒否する。UUIDは正規形・重複なし・1〜20件をRustで検証し、昇順に正規化する。
存在しない商品は全体を失敗させ、自動スキップしない。

一括snapshotTokenは、バージョン識別子、正規順序の各商品UUIDと既存の単品snapshotTokenをSHA-256へ入力する。
UUID集合の追加／削除、商品全情報、画像メタデータと順序、全属性定義、保存値、現在所属・グループ情報、
画像の利用可否・候補Issueの変化で確認を無効化する。入力順の違いだけでは変化しない。
既存の単品トークン生成は変更しない。実行バージョン内の一時的な変更検出に限り、永続化・認証には使わない。

上限は名前付きRust定数で20商品・200画像・登録済みサイズ合計1GiB。
画像数とサイズはchecked_addで集計し、不正サイズを拒否する。超過理由は専用エラーで通知する。
上限内でも実コピーは既存のファイル単位20MiB制限・サイズ一致・SHA-256一致を必須とする。

## 出力構造と互換性

```text
ListingPilot_Batch_{YYYYMMDD}_{batchUUID}/
  {productUUID}/
    product.csv
    attributes.csv
    images.csv
    images/
      0001-{imageUUID}.{jpg|png|webp}
```

バッチUUIDは出力処理ごとに生成し、パスには商品名・SKU・グループ名を使わない。
CSVの列・列順・BOM・CRLF・引用符・数式拒否・Number文字列精度・NULLと0円・内部メモ非公開はADR 0010を維持する。
画像相対パスは商品フォルダーを起点とし、画像番号・先頭メイン画像は商品単位に扱う。
現在グループの有効で保存済みの属性だけを出力する。同名属性はUUIDで区別し、旧グループ値・非表示値は保持して出力しない。
Schema Version 5と全Migrationを変更しない。単品API・フォルダー名・トークン・エラー契約を維持する。

## 全件成功・ステージングと確定

単品エクスポートをN回呼ばず、batch_export_serviceが出力全体を所有する。

1. メディアpermitを取得し、単一SQLite読取トランザクションで全Snapshotを取得する。
2. DB Mutex解放後にlisting_preview_serviceのbuildで候補を生成し、一括トークン・警告承認・上限を検証する。
3. 全商品のCSVを事前生成して数式リスク等を検査した後、Rustネイティブダイアログで出力先を選択する。
4. 選択後は全Snapshot・トークン・警告・CSVを再検証する。
5. 1つのWorkspaceへ全商品の固定CSVと原本画像を順次書き込む。コピー中はDB Mutexを保持しない。
6. 各ファイルをsyncした後、短いIMMEDIATE内で全Snapshotを再照合し、出力先も再検証する。
7. 全件一致時だけ既存MoveFileExW（flags=0）でステージング全体を非置換移動する。

最終照合から確定まで、DB Mutex・IMMEDIATE・メディアpermitによる既存の排他方針を維持する。
読取トランザクションはdropで終了し、完成公開後に失敗し得るCOMMITを実行しない。
商品単位のprepare/write_product、export_csv、MediaStorage::copy_originalを単品と共用する。
新しい依存、DBテーブル、汎用書込フレームワークを追加しない。

Workspaceは自分が作成したディレクトリとファイルだけを記録し、固定された構造・名称だけを受け付ける。
create_new、管理領域拒否、パストラバーサル・リンク・junction/reparse point拒否を維持する。
通常失敗ではファイル、次にディレクトリを逆順で個別に削除する。再帰清掃を使わない。
未知の項目・リンク・清掃失敗は保持して元エラーと残存場所を返す。移動結果不明では自動清掃しない。
起動時にエクスポートの残存ステージングを消す処理は追加しない。

成功・キャンセル・失敗は既存ExportReportで区別する。成功は出力先・商品数・属性数・画像数・警告有無を返す。
通常のエラーは既存AppError経路、清掃失敗／結果不明はFailedの元エラー・残存場所・清掃失敗フラグを使う。

## 保証の限界と対象外

同一ユーザーの別プログラムが検査直後に任意のファイルを差し替える攻撃全般や、電源断後の耐久性を保証する変更ではない。
通常DB・元画像を更新しない。ネットワークドライブ、実ディスク故障、インストーラー操作は別途検証が必要。
開発監視中のリポジトリ内では最終移動がOSエラー5となることを確認し、保護を緩和せずリポジトリ外で正常系を検証する。
ロック元の断定はしていない。調査記録は [検証記録](../verification.md) を参照。

販売先専用／統合CSV、部分成功、スキップ、処理開始後キャンセル、進捗率、並列コピー、出力履歴、
バックグラウンド処理、検索・ページネーションは追加しない。
