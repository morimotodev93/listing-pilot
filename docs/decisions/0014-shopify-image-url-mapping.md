## 背景・検証結果

Listing PilotはローカルのJPEG/PNG/WebP原本を画像UUID・商品UUID・`sort_order`・SHA-256で管理し、Shopify用には現状10列・画像なしの商品CSVを生成する。Shopify商品CSVにローカルファイルパスを指定しても画像は取り込めないため、公開HTTPS画像URLとの対応付けが必要である。

Phase 5.2.0では青い小皿の4画像をShopify Filesに手動アップロードし、得られた `cdn.shopify.com` のURLを使った新規商品向けCSVを検証した。

- **テストA：画像1枚**の商品登録に成功し、画像が表示された。
- **テストB：画像4枚**の商品登録に成功し、正面・上面・側面・裏面の4枚が期待した順に表示された。1枚目がメイン画像だった。
- 下書き状態の新規商品に対する検証である。**画像URLの長期的な有効性、altテキストの再エクスポート値、同一Handleの再取込・既存画像更新、Shopify APIでのアップロードは未検証**であり、今回の成功から保証しない。

## 決定1：ローカル画像管理とShopify URL設定を別画面に分ける

- 既存の商品画像画面は、画像の追加・閲覧・並び替え・削除を主目的として維持する。狭いサムネイル欄に長いURL入力欄を並べない。
- 商品画像から **「Shopify画像URLを設定」** を開く。専用ダイアログまたは独立パネルに、画像を現在の`sort_order`順で縦に列挙する。
- 対象ストアの`*.myshopify.com`ドメインを利用者が入力・選択する専用UIを設け、現在の対象ストアを明示する。ストア切替時も未保存内容を黙って破棄せず、ストアAの入力や確認をストアBへ流用しない。
- 各行にサムネイル、画像順序、短い識別情報、フル幅のURL入力欄、設定状態、任意の画像altテキスト入力欄を設ける（自動推測はしない）。
- **一括貼り付け**を提供する。1行1URLを現在の画像順に対応させ、件数・空欄・形式を検査した結果と、対象ストア・画像UUID・対応サムネイルを保存前に確認してから一括適用する。保存は全件を単一SQLiteトランザクションで扱い、件数不一致・競合・途中失敗で既存設定を部分更新しない。
- 入力欄は空欄（未設定）を許す。未設定は明示表示し、保存前の編集内容を黙って破棄しない。保存完了・競合・失敗を区別して表示する。
- URLの対応は画像の表示番号ではなく**不変の画像UUID**で保持する。画像を並び替えてもURLとaltテキストは画像に追従し、CSVの`Image position`だけを再計算する。

## 決定2：外部URLをローカルSQLiteで画像・ストア別に保持する

- `product_images`にShopify固有のURL列を追加せず、画像UUIDを参照する**別テーブル**を設ける。Shopify以外の販売先や複数ストアを区別できるよう、`platform`と`store_key`を含める。
- `store_key`は利用者が指定した対象ストアの正規化された`*.myshopify.com`ドメインとする。Rust側で制御文字を拒否し、前後の空白除去・ASCII小文字化後、単一のストアラベル（ASCII英数字・ハイフン、1〜63文字、先頭末尾は英数字）＋`.myshopify.com`に厳密に限定する。scheme・パス・ポート・ユーザー情報・ワイルドカード・追加サブドメイン・類似ドメインは受け付けない。現段階では認証やShopify API連携は行わず、ストアの実在・所有権を検証したとは扱わない。
- 最小の概念モデル：`image_id`、`platform`、`store_key`、`url`、`image_sha256`、任意の`alt_text`、更新時刻。主キーは `(image_id, platform, store_key)`。`image_sha256`は登録時点の管理原本のハッシュを記録し、出力時に現在の画像メタデータと照合する。
- このハッシュの一致が**Shopify CDN上の画像内容まで同一と証明するわけではない**。手動アップロードしたURLが対象画像を指すかは、設定時のサムネイル照合と利用者確認で担保する。
- 新しいURL対応テーブルは**既存Schema v5からの番号付き・前進のみのMigration 0006**で追加する。既存0001〜0005を書き換えず、既存の商品・画像・カスタム属性を保持し、失敗時はトランザクション全体を戻す。`foreign_key_check`と旧データ保持・移行失敗テストを必須とする。
- URL対応テーブルの`image_id`は`product_images.id`への外部キーとし、**`ON DELETE CASCADE`**を採用する。画像行を削除すると、その画像UUIDに属する全platform・store_keyのURL設定行も同じSQLiteトランザクション内で削除される。既存の`product_images.product_id`の**`ON DELETE RESTRICT`は変更しない**。商品削除は既存どおり対象画像を明示削除してから商品を削除する。
- 既存の画像削除・商品削除サービスの共通permit、事前検査・トランザクション内の再照合、失敗時保護、COMMIT後の対象原本の隔離を維持する。URL設定の変更自体で管理原本を変更せず、他商品・他画像のURL設定や管理原本に影響を与えない。
- COMMIT失敗時は既存のautocommit確認と参照再照会の方針を維持し、URL対応行も含めて整合性を確認する。ロールバックでは画像行とURL設定をともに保持する。削除確定と参照なしを確認できた場合だけ既存の隔離へ進み、結果不明・参照確認不能時は原本を保持して成功を断定せず、再起動・状態確認を案内する。削除・ロールバック・COMMIT失敗／結果不明時の保護を実装時にテストする。
- DBと`media/`を一組としてバックアップする既存原則を維持する。URL情報は機密情報に準じて扱い、不必要にログへ出さない。

## 決定3：公開画像URLの入力・保存の安全性

- Phase 5.2.2の初期対象は**Shopify Filesからコピーした`https://cdn.shopify.com/`の公開画像URLのみ**とする。Rustで絶対URLとして解析し、schemeが`https`、hostnameが`cdn.shopify.com`と完全一致することを検証する。ホスト名の部分一致・類似ドメイン・サブドメイン・末尾ドットによる別表記を許さない。
- ユーザー情報、非標準ポート（443以外）、制御文字（パーセント表現を含む）、空白、バックスラッシュ、フラグメントや曖昧なauthorityなど危険な形式を拒否する。解析時の自動補正で危険な入力を受理しない。正当な画像URLの**クエリ文字列は許可し、保存・CSV出力時も保持**する。
- URL長はクエリを含む**UTF-8で4,096バイト以内**とし、入力値と保存するURLの両方に適用する。重複URLは**同一商品・同一platform・同一store_key内の異なる画像UUID間**で検出し、保存・画像付き出力を拒否する。比較は検証後のURL表現に統一し、クエリを除去・並べ替えない。同じ画像UUIDの設定更新は重複とせず、空欄は検査対象外とする。他商品・他ストアの設定にはこの重複制限を広げない。
- **URL形式の検証と実在・画像内容の検証は別**。初期版はネットワークアクセスによる存在確認（HTTP HEAD等）、画像ダウンロード、Shopify API連携を行わない。形式の妥当性はリモート画像の実在や内容の一致を保証せず、「形式OK」を「Shopifyで取得可能」と表示しない。
- ローカル画像ファイルの絶対パス、`file:`、`data:`、スクリプトURL、管理画面の認証付きURLは受け付けない。URL入力を理由にCSP、Asset Protocol、Tauri capabilitiesを広げない。
- 複数ストアのURLや間違った画像の貼付けは利用者が識別できるよう、**ストア名と画像サムネイルを保存前・出力前に明示**する。

### 画像altテキスト（2026-11-20確定）

- 任意入力で、最大**512 Unicode文字**とする。UIには**125文字以内を推奨**と表示し、推奨超過だけでは拒否しない。空欄を許可し、CSVの`Image alt text`も空欄にする。ファイル名・管理メモから自動生成しない。
- 文字数はRustの`chars().count()`に相当するUnicodeスカラー値数とし、UTF-8バイト数・UTF-16コード単位数では数えない。UIの文字数表示・推奨判定、Rustの保存検証、CSV出力検証で同じ数え方を使う。
- altは単一行とし、CR・LF・タブを含む制御文字とUnicode行区切り（U+2028／U+2029）を拒否する。検査前のtrimや改行除去で不正入力を隠さず、黙って切り詰めない。CSV数式インジェクションは既存の`export_csv::text`と同じ厳格な規則（先頭の空白・制御／不可視文字を考慮した`= + - @`の検出、CR／LF後の各行検査）で保存時・出力時とも検証する。

## 決定4：Shopify CSVは「画像なし」と「画像URL付き」の二方式

- **画像なし**：Phase 5.1の10列、1商品1行、`shopify-products.csv`、既存IPC・確認と出力契約を維持する。URL未設定でも使用できる。
- **画像URL付き**：既存10列の末尾に次の3列を追加した**13列**の新規商品登録用CSVを生成する。

```csv
Product image URL,Image position,Image alt text
```

- 画像1枚につきCSV1行。最初の行は商品情報＋1枚目の画像URL・位置1、2枚目以降は同じ`URL handle`と各画像URL・位置・altを記載し、商品基本情報欄は空欄にする。商品を跨ぐ行順と各画像の順序は決定的にする。
- 画像順は現在の `sort_order` に従い、`Image position`を**1始まり**で生成する。画像UUIDとURLの関係は並び替え後も維持する。初期版ではバリエーション画像、画像削除・既存Shopify商品の更新を扱わない。
- 画像URL付きモードでは、対象各商品について画像が1枚以上あり、**その商品の全管理画像に選択ストア向けの有効なURLが設定済み**であることを条件とする。未設定・重複・不正URL・SHA不一致があれば対象商品を明示し、**全件出力を停止**する。黙って画像を飛ばしたり、部分成功させたりしない。
- altテキストは決定3の任意入力・最大512 Unicode文字・単一行の規則に従う。未設定はCSVでも空欄とし、画像ファイル名・管理メモから勝手に生成しない。
- Shopify用共通ルールの`draft`／`false`固定、JPYストアの**利用者による明示確認**、SKU・価格・数式検証、15MB未満のUTF-8バイト長検証、UTF-8 BOMなし・LF、CSV引用符エスケープを維持する。
- 出力は**CSVのみ**とし、管理原本をコピーしない。画像なしモードに汎用の200画像・1GiB制約を後付けせず、画像付きでも実際のCSVサイズと採用した商品・画像数制約で判定する。

## 決定5：プレビュー・変更検出と安全な確定

- Shopify画面では選択対象（1〜20商品）のほか、**出力モード・対象ストア・画像の枚数・URL設定状況・メイン画像・画像順序**を確認できるようにする。
- URL設定の保存は画像UUID・`platform`・正規化済み`store_key`で対象を限定する。画面取得時の画像構成・全画像UUIDと順序・SHA-256・現在のURL／alt設定（未設定を含む）を保存時の短いSQLiteトランザクション内で最新状態と照合する。古い画面からの保存は競合として全件拒否し、暗黙の上書き・自動再送信をしない。ストアAとストアBの設定を混用せず、一括貼り付けも同じ照合と全件一体の保存契約に従う。
- 画像URL付き出力には、モードとストア識別子、画像UUID・現在順序・SHA-256・URL・alt情報を含む**Shopify画像付き専用スナップショットトークン**を設ける。Phase 5.1の画像なしトークンと混用しない。
- プレビューから出力までに商品・画像順・URLマッピング・ストア選択が変われば古い確認を拒否する。警告があればトークンに結び付いた再確認を必須とし、プレビュー再読込・エラー・キャンセル後は承認を失効させる。
- 出力は、事前準備→Rustネイティブの出力先選択→再検証→同一親へのステージングとsync→短いSQLite `IMMEDIATE`で商品およびURL対応の最終照合→`Workspace.finish()`による**1回だけの非置換確定**とする。DB Mutexを長いファイルI/O中に保持しない。
- 元画像・DB・既存の完成出力を上書きしない。通常失敗時は当該処理が作成したファイルだけを限定清掃する。結果不明時は保持する。既存の汎用単品／一括出力の契約を変更しない。
- 既存Handleの上書きをオフにした**新規商品**の検証を基本とする。アプリ単独でShopify上の重複Handleや実際のJPY設定を検知できると主張しない。

## 対象外・未確定事項

- 自動アップロード、Shopify Admin API・認証、商品更新／同期、公開状態の変更、CSVによる画像削除、メタフィールド、サイズ・色のバリエーションは対象外。
- URLの有効期限やCDN資産の恒久性は保証しない。Shopify側の画像複製や不要ファイルの掃除も自動化しない。
- 従来の**「実装前に確定する細部」4項目は2026-11-20に確定済み**：画像URLは`https://cdn.shopify.com/`のみ、画像削除時はMigration 0006の外部キー`ON DELETE CASCADE`、altは任意・最大512 Unicode文字／UI推奨125文字、複数ストアは専用入力・選択UIと正規化ドメインによる分離・古い画面の保存拒否とする。
- 実装時に残る具体化・レビュー事項は、採用するURL解析方法と比較用表現、URL対応テーブルの具体的なDDL・制約、保存時の変更検出用IPC／トークンの形式、専用UIの配置・競合表示、障害注入テストの方法とする。上記4判断と既存のデータ保護・専用出力トークンの契約を変えずに具体化し、実装・動作確認は別途行う。
- 配布版・別PC・電源断・Windowsのリポジトリ監視下で起きる最終移動エラー5は本ADRで解決したと扱わない。
